# オープンワールド恋愛シミュレーション 設計仕様書

- 作成日: 2026-11-01
- ステータス: レビュー待ち

## 1. 目的と前提

### 目的
2D見下ろし視点の街を自由に歩き回り、ヒロインと出会って関係を深めるオープンワールド型の恋愛シミュレーションゲームを、ブラウザで動く形で作る。キャラクターの立ち絵と会話背景は Gemini の画像生成で実写風に作成する。

### ユーザー合意事項
- ゲーム形式: オープンワールド(2Dマップ探索型)
- 舞台: 現代の地方都市・大学生活
- ヒロイン: 3人
- 画像: Gemini で **開発時に一括生成** し、ゲームに同梱する(実行時生成はしない)
- 実装方式: Phaser 3 + 素の JavaScript(ビルドなし)

### 前提・制約
- 登場人物はすべて **成人(20〜24歳)**。性的な表現は扱わない(全年齢向けの恋愛表現)。
- 実在人物・既存作品のキャラクターに似せない、オリジナルのデザインとする。
- 「リアル」= 会話画面の立ち絵・背景が実写風であること。マップはドット絵風で、表現を使い分ける。
- Gemini API キーはブラウザに露出させない(生成スクリプトのみが使用)。
- 既存の `index.html`(トレード端末ページ)には手を入れず、ゲームは `game/` 以下に独立させる。

### 成功条件
1. ブラウザで `game/index.html` を開くと、タイトル → 街の探索 → ヒロインとの会話 → 選択肢による好感度変化 → エンディング まで通して遊べる。
2. 3人のヒロインそれぞれに、Gemini 生成の実写風立ち絵(表情差分 5 種)と、会話背景 8 か所がそろっている。
3. セーブ/ロードができる。
4. ゲームロジックの単体テストと、Playwright による起動確認が通る。

## 2. 全体構成

```
game/
  index.html            … 起動ページ(Phaser 3 を CDN から読み込む)
  src/
    main.js             … Phaser の初期化、シーン登録
    scenes/
      TitleScene.js     … タイトル、ニューゲーム/コンティニュー
      WorldScene.js     … 街マップ探索(移動、当たり判定、話しかけ)
      DialogueScene.js  … 会話画面(背景、立ち絵、テキスト、選択肢)
      HUDScene.js       … 日付・曜日・時間帯・所持金・ステータス表示
      EndingScene.js    … エンディング表示
    systems/
      TimeSystem.js     … 日付・時間帯の進行
      Affection.js      … 好感度・イベント進行度の管理
      Schedule.js       … 曜日×時間帯ごとのヒロイン配置
      SaveSystem.js     … localStorage へのセーブ/ロード
      DialogueRunner.js … 会話データの解釈(選択肢、条件分岐、効果の適用)
    data/
      map.json          … 街のタイルマップ
      heroines.json     … ヒロイン設定、スケジュール、画像の対応
      locations.json    … 場所の定義(マップ上の範囲、背景画像、行動)
      dialogues/*.json  … 会話・イベントデータ
  assets/
    portraits/<id>/<expression>.png  … 立ち絵(透過 PNG)
    backgrounds/<location>.jpg       … 会話背景
    tiles/                           … マップタイル(コードで生成するドット絵風)
  tests/                … ロジックの単体テスト(Node 標準の test runner)
tools/
  generate_portraits.py … Gemini 画像一括生成スクリプト
  prompts/              … プロンプトのテンプレート
```

### 方針
- **データとコードを分離**する。シナリオ・スケジュール・会話は JSON にし、シナリオ追加でコードを触らずに済むようにする。
- `systems/` は Phaser に依存しない純粋な JS モジュールにし、Node で単体テストできるようにする。
- シーン間の状態は 1 つの `GameState` オブジェクト(時間・好感度・ステータス・所持金・フラグ)にまとめ、各システムはそれを操作する関数を提供する。

## 3. ゲームの流れ

### 3.1 期間と時間
- 期間は **4月第1週〜7月末(約16週間)**。
- 1日は **朝 / 昼 / 夕 / 夜** の 4 時間帯。
- **歩くだけでは時間は進まない**。次の行動で時間帯が 1 つ進む:
  - ヒロインとの会話・イベント
  - 授業・バイト・運動などの場所での行動
  - 自宅で休む(夜に休むと翌朝へ)
- 平日の昼は授業(キャンパスで受けると知力が上がる)。週末は授業なし。

### 3.2 マップ
1 枚の街マップに 8 か所:

| ID | 場所 | 主な行動 |
|---|---|---|
| campus | 大学キャンパス | 授業(知力+) |
| library | 図書館 | 自習(知力+) |
| shopping | 駅前商店街 | プレゼント購入 |
| cafe | カフェ(バイト先) | バイト(所持金+) |
| seaside | 海辺の公園 | ランニング(体力+) |
| shrine | 神社 | お参り(魅力+) |
| home | 自宅 | 休む、セーブ |
| station | 駅 | (イベント用) |

- プレイヤーは矢印キー/WASD、スマホでは画面のバーチャルパッドで移動する。
- 場所の入口に近づくと行動メニューを出す。ヒロインの近くで決定キーを押すと会話する。

### 3.3 ヒロイン(仮案。詳細はキャラ設定作成時に詰める)

| ID | 立場 | 性格 | 主な居場所 |
|---|---|---|---|
| hina | 同じ学科の同級生(20歳) | 明るく行動的 | キャンパス、商店街 |
| rei | バイト先カフェの先輩(23歳) | 大人っぽく面倒見がよい | カフェ、海辺 |
| shiori | 図書館の司書(24歳) | 物静かで読書家 | 図書館、神社 |

- 各ヒロインは `heroines.json` に、曜日(平日/土/日)×時間帯ごとの居場所を持つ。いない時間帯もある。
- マップ上ではヒロインをドット絵の小さなキャラで表示し、頭上に名前を出す。

### 3.4 好感度とイベント
- 好感度はヒロインごとに 0〜100。
- 増減の要因: 会話の選択肢、プレゼント(好みで変化量が変わる)、デート。
- 同じ日に同じヒロインと何度話しても、通常会話で好感度が上がるのは 1 日 1 回まで。
- **個別イベントは各ヒロイン 5 段階**。開放条件の例: 好感度 ≥ 20/40/60/75/90、加えてステータス条件や曜日・場所条件。
- イベントは会話データ内で `condition` と `effects` で表す。

### 3.5 エンディング
- 7月末の「夏祭り」の日に判定する。
- 最終イベント(5段階目)まで見たヒロインのうち、好感度が最も高いヒロインの個別エンディングになる。
- 該当なしの場合は「友達エンド」。
- エンディング後はタイトルへ戻る(到達済みエンディングを記録)。

### 3.6 サブ要素
- **所持金**: バイトで増え、プレゼント・デートで使う。
- **ステータス**: 知力・魅力・体力(各 0〜100)。一部イベントの条件になる。

### 3.7 会話画面
- 画面全体に場所の背景(実写風)を表示し、中央にヒロインの立ち絵を出す。
- 表情差分 5 種: `normal`, `smile`, `shy`, `surprised`, `sad`。会話の行ごとに切り替える。
- 下部にテキストウィンドウ(1 文字ずつ表示、クリック/キーで送る)、必要に応じて選択肢ボタン。

### 3.8 会話データ形式(例)
```json
{
  "id": "hina_event_1",
  "heroine": "hina",
  "location": "campus",
  "condition": { "affection": { "hina": 20 }, "time": ["noon"] },
  "lines": [
    { "speaker": "hina", "expression": "smile", "text": "あ、同じ講義だったんだ!" },
    { "choice": [
      { "text": "隣いい?", "effects": { "affection": { "hina": 5 } }, "next": "a" },
      { "text": "軽く会釈する", "effects": { "affection": { "hina": 1 } }, "next": "b" }
    ]}
  ],
  "branches": { "a": [ ... ], "b": [ ... ] },
  "onComplete": { "setFlag": "hina_event_1_done" }
}
```

### 3.9 セーブ
- localStorage に 3 スロット。自宅でのみセーブ可、タイトルからロード可。
- データにはバージョン番号を持たせ、読み込めないデータは「破損」と表示して無視する。

## 4. Gemini 画像生成の流れ

### 4.1 スクリプト `tools/generate_portraits.py`
開発時に手動実行する。API キーは環境変数 `GEMINI_API_KEY` から読む。

1. `heroines.json` の外見設定(年齢 20〜24 歳の成人、髪型、服装、雰囲気)と `tools/prompts/` のテンプレートからプロンプトを組み立てる。
2. **基本立ち絵(normal)を生成**: 実写風、膝上構図、正面寄り、背景は単色グリーン(クロマキー用)。
3. **表情差分 4 種を生成**: 基本立ち絵を参照画像として渡し、表情のみ変更するよう指示して顔・服装の一貫性を保つ。
4. Pillow でグリーン背景を除去し、透過 PNG として `game/assets/portraits/<id>/<expression>.png` に保存する。サイズは高さ 1600px に統一する。
5. 会話背景 8 か所を実写風(人物なし)で生成し、`game/assets/backgrounds/<location>.jpg` に保存する(1920×1080)。
6. 生成結果の一覧ページ `tools/out/contact_sheet.html` を出力する。

### 4.2 オプション
- `--only hina:smile` … 指定した画像だけ作り直す
- `--force` … 既存ファイルがあっても作り直す
- 既定では既存ファイルはスキップする(途中から再開できる)

### 4.3 モデル
実装時に API でモデル一覧を取得し、その時点で使える画像生成・編集対応(参照画像入力可)の Gemini モデルを選ぶ。モデル ID はスクリプト内の定数 1 か所にまとめる。

### 4.4 エラー処理
- レート制限・一時的なエラー: 指数バックオフで最大 4 回まで再試行。
- 安全フィルタで拒否された場合: その画像をスキップしてログに残し、最後に一覧を表示する。
- API キー未設定: 設定方法を表示して終了する。

### 4.5 画像がない場合
ゲームは画像ファイルが見つからないとき、仮の立ち絵(名前入りのシルエット)と単色背景で代わりに表示する。これにより API キーがなくてもゲーム本体の開発・確認ができる。

## 5. エラー処理(ゲーム側)
- JSON データの読み込み失敗: タイトル画面にエラーを表示する。
- 会話データ内の存在しない参照(分岐先・ヒロイン ID): 開発時の検証テストで検出する。
- セーブデータ破損: 該当スロットを「破損」と表示し、上書きのみ許可する。

## 6. テスト
- **単体テスト**(Node 標準の `node --test`): TimeSystem、Affection、Schedule、SaveSystem、DialogueRunner。
- **データ検証テスト**: すべての会話 JSON について、分岐先・ヒロイン ID・場所 ID・表情名が定義済みであることを確認する。
- **動作確認**: Playwright で `game/index.html` を起動し、タイトル → 探索 → 会話 → 選択肢までを自動で操作してスクリーンショットを撮る。

## 7. 範囲外(今回はやらない)
- 実行時の画像生成・AI 会話生成
- BGM・効果音(枠だけ用意し、音源は後回し)
- 3D 表現、複数マップ
- オンライン機能

## 8. 必要な準備(ユーザー作業)
- Google AI Studio で Gemini API キーを発行し、クラウド環境の設定(Network secrets、なければ環境変数)に `GEMINI_API_KEY` として登録する。新しいセッションから有効になる。
